## Section 3 · Constitutional invariants (locked per D-11)

1. **`confidence_score` (numeric 0–100) is authoritative** per R-11.v1.0.0
2. **`band` is DERIVED from score** at Router boundary per §7.8 J1 Rule 15 · band is presentation-tier · score is logical-tier
3. **Guardian rejects rows where `band != derived(score)`** (band drift check installed at Stage 1a code time)
4. **`unknown` band is FAIL-CLOSED** per §7.7 H1 · Guardian rejects promotion of `unknown`-banded row to AUTHORITATIVE
5. **`unknown` ≠ `very_low`** — an unresolved row (score not authored) is distinct from a low-confidence row (score explicitly authored < 50) · per §7.7 H1 axis-specific rule
6. **Score is the numeric authority · band is the display label** — Chat/NEX1 receive both · never band alone · never band derived from a non-existent score

## Section 4 · Special handling

- **Score = null** → `band = "unknown"` · Guardian rejects promotion to AUTHORITATIVE
- **Score = 0** → `band = "very_low"` (explicit low-confidence · legitimate result of classification · not a substitute for unknown)
- **Score = 100** → `band = "very_high"` · reserved · Guardian may enforce founder-verified+multi-source requirement at Stage 1a code time
- **Score outside [0, 100]** → Guardian rejects the write with reason `confidence_score_out_of_range`

Band-drift condition (Guardian violation examples):
- `score=85 AND band=very_high` → REJECT · reason `band_drift_score_85_should_derive_good`
- `score=null AND band=high` → REJECT · reason `unknown_score_cannot_have_named_band`
- `score=42 AND band=moderate` → REJECT · reason `band_drift_score_42_should_derive_very_low`
