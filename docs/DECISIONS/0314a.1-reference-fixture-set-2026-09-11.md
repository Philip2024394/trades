## Section 2 · Locked fixture strategy

**Baseline:** **33 fixtures minimum** at Stage 1a smallest-certified-path exit
- 11 Stage 1 R-rules × 3 fixtures each (positive · negative · fail-closed/unknown)

**Target:** **50–75 fixtures** at Stage 1b production writes commencement
- Adds boundary cases · cross-rule interaction · regression baselines · language-variant cases

**Fixture location:** **isolated test schema** (`nex_test.*` or similar) · NEVER production `nex.*`

**Fixture format:**
```
{
  fixture_id: string             (deterministic UUID)
  r_rule: string                 (R-01 · R-03 · R-05 · R-07 · R-11 · R-12 · R-13 · R-17 · R-18 · R-20 · cross_substrate)
  input_row: JSON                (canonical row shape)
  expected_verdict: string       (PASS · REJECT · UNKNOWN · CANDIDATE_FLAG · CONTRADICTION_RECORDED)
  expected_reason: string        (named fail-closed reason where applicable)
  expected_confidence_band: string (per ADR-0314a.2.j band)
  cross_rule_interactions: string[]  (which other R-rules this fixture also tests)
  fixture_version: string        (fixture_set.v1.0.0 · immutable per version)
}
```

**Fixture set is VERSIONED** per R-17 · immutable at each version · new fixtures added as new versions (e.g. `fixture_set.v1.0.0 → v1.1.0` when adversarial corpus added at Stage 5)

**Adversarial fixtures DEFERRED to Stage 5** per ADR-0314a.2.ac · not part of Stage 1 authoring

## Section 4 · Cross-rule fixture requirement

Some fixtures test multiple R-rules simultaneously:

- **Cross-rule composite:** e.g. a row requiring R-01 plausibility AND R-11 confidence AND R-18 verifier envelope · all three must pass together OR all three fail together (per verifier composition semantics)
- **Rule-set-version manifest test:** verifies R-18 `rule_set_version` composes correctly from individual `rule_version` values
- **Founder-override test:** verifies R-18 founder-authorised path overrides automatic verdict · records both original and override per R-18 provenance

Cross-rule fixtures add ~5–10 additional fixtures beyond the baseline 33 · reaching the 50-75 target at Stage 1b commencement.

## Section 6 · Fixture authoring workflow

**Locked workflow:**
1. Master AI drafts fixture cases as `{input_row · expected_verdict · expected_reason}` triples
2. Founder reviews · approves each fixture OR bulk-approves per rule
3. Approved fixtures added to `fixture_set.vN.N.N` (versioned)
4. Fixtures live in isolated test schema · NEVER touch production nex.*
5. Verifier + Guardian run against fixture set · must pass 100% deterministically
6. Any fixture that fails deterministic reproducibility (same input · same output across multiple runs) is a Stage 1a exit blocker

**Fixture retention:** all-time (versioned · immutable per version)
