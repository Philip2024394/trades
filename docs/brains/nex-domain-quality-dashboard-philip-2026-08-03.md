# NEX Domain Quality Dashboard + Gap Detection + Heat Maps + Recommendation Graph + Design Pattern Library

## The Doctrine

Philip 2026-08-03: *"If I were designing NEX from this point onward, I wouldn't rush into Domain 003. I'd introduce a new layer: Domain Quality Dashboard."*

This doctrine formalises FIVE refinements to the existing Coverage/Health/Dashboard doctrine — the operational cockpit for the Knowledge Layer as it scales.

## Refinement 1 · Domain Quality Dashboard (live scorecard per domain)

**Rule:** every domain has a live scorecard visible on one screen. Format:

| Metric | Staircase | Kitchen | Doors | (future) |
|---|---|---|---|---|
| Coverage | 94% | 67% | 4% | ... |
| FAQs | 1,980 | 55 | 0 | ... |
| Brain Docs | 30 | 22 | 0 | ... |
| Images | 821 | 0 | 0 | ... |
| A+ References | 31 | 1 | 0 | ... |
| Shared Articles inherited | 8 | 8 | 8 | ... |
| Confidence | High | High | Unknown | ... |
| Maturity | Silver+ | Silver | Bronze | ... |

**Immediately you know where to invest next.** The dashboard is the AUTHORING PRIORITY SIGNAL.

Generated by: `scripts/build-nex-knowledge-dashboard.mjs` (reads every `data/nex-knowledge/*/knowledge.yaml` + counts files + queries learning log).

## Refinement 2 · Knowledge Gap Detection

**Rule:** every query with confidence <0.7 (per Brain 14) generates a KNOWLEDGE TASK, not just a log entry.

Example:

> User asks: *"Can I fit underfloor heating beneath engineered oak flooring?"*
>
> Pipeline:
> - Knowledge found: 72%
> - Confidence: 0.68
> - Brain 14 gate: triggered
> - Needs clarification: true
>
> **NEW behaviour:** instead of just logging the query, Nex creates a knowledge task:
> - `missing_topic: "underfloor heating + engineered oak flooring"`
> - `domain: flooring` (or `staircase` if that's what the retrieval attempted)
> - `sub_area: underfloor_heating`
> - `priority: medium` (based on frequency)
> - `assigned_to: philip` (or Claude-drafts-first per authoring-workflow)

Knowledge tasks accumulate in `data/nex-knowledge-tasks.jsonl` and are surfaced on the Dashboard's TOP AUTHORING PRIORITIES section.

**This closes the loop:** every user question that fails to answer well becomes the input to the next authoring session. Composes with Philip's authoring workflow (*"Aim to write 100k questions, not 100k articles"*).

## Refinement 4 · Recommendation Graph

**Rule:** every domain declares its RELATIONSHIPS to other elements. These form a graph.

Example:

```
Kitchen
  matches → Oak Flooring
  matches → Oak Staircase
  matches → Four Panel Doors
  matches → Wall Panelling
  matches → Dining Furniture

Oak Staircase
  matches → Oak Flooring
  matches → Kitchen
  matches → Four Panel Doors
  matches → Oak Handrail
  matches → Continuous Timber Balustrade

Four Panel Doors
  matches → Oak Staircase
  matches → Shaker Kitchen
  matches → Wall Panelling
```

**This turns Nex into a design assistant that PROACTIVELY coordinates an entire home.**

Encoded via each domain's `knowledge.yaml`:

```yaml
recommendation_graph:
  matches:
    - domain: flooring
      when_style: [modern_shaker, traditional]
      via: shared_timber_species
    - domain: staircase
      when_style: [traditional_british, modern_shaker]
      via: shared_timber_species + shared_paint_palette
    - domain: doors
      when_style: [any]
      via: shared_moulding_profiles
  avoids:
    - domain: bathroom
      why: unrelated_material_context
```

The existing Recommendation Engine (Phase D.6) already reads coordination rules — this refinement adds STRUCTURED GRAPH DATA to those rules for machine reasoning.

## Refinement 5 · Design Pattern Library

**Rule:** every A+ specimen becomes a NAMED PATTERN with structured metadata.

Example — from the flagship kitchen+staircase specimens shipped earlier today:

```yaml
pattern: modern_oak_minimal
description: Straight staircase + glass balustrade + oak handrail paired with handleless kitchen + quartz worktops + large porcelain tiles
uses:
  - straight_staircase
  - glass_balustrade
  - oak_handrail
  - handleless_kitchen
  - quartz_worktops
  - large_porcelain_tiles
style: contemporary
difficulty: medium
budget: £££
pairs_with:
  - walnut_accents
  - black_steel
  - warm_white_LED
avoid:
  - victorian_mouldings
  - pine_doors
  - gloss_cherry_cabinets
reference_specimens:
  - https://ik.imagekit.io/5vv5pw26q/ChatGPT%20Image%20Aug%203,%202026,%2010_33_28%20PM.png (compact variant)
  - https://ik.imagekit.io/5vv5pw26q/ChatGPT%20Image%20Aug%203,%202026,%2009_08_25%20PM.png (walnut+horizontal-metal variant)
```

Then Nex can answer *"show me kitchens similar to this staircase"* by:
1. Identifying the staircase's pattern.
2. Finding the pattern's `pairs_with` list.
3. Retrieving all A+ specimens tagged with those elements.

Without relying on keyword search alone. **This is DNA-based retrieval** — patterns are the design DNA.

Stored in: `data/nex-knowledge/_shared/design-patterns/{pattern-id}.yaml`

## Refinement 6 · Domain Independence Measure

**Rule:** the platform is measured by how EASILY a new domain can be added, not by how many domains exist.

**Target:**

- **Bronze in 1 day** — a new domain with 20 FAQs · 5 A+ images · 3 articles · declared knowledge.yaml.
- **Silver in 1 week** — 100 FAQs · 15 A+ images · 10 articles · full sub-area declarations · cross-domain dependencies declared.
- **Gold over time** — 500+ FAQs · 50+ A+ images · 25+ articles · production tool integrations · Learning Loops producing measurable improvements.

**If these targets are consistently achievable WITHOUT modifying the pipeline · Router · Foundation Brains · or Knowledge Layer runtime → the architecture is proven.**

If a new domain requires infrastructure changes → the abstractions are wrong and must be refined BEFORE adding more domains.
