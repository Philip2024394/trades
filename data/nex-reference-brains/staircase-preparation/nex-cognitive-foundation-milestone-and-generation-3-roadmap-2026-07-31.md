## Roadmap Admission Rule (Philip 2026-07-31 · 5 questions · updated with Creator Question 5)

Every proposed feature must answer five questions before it becomes part of NEX:

1. **What real user problem does it solve?**
2. **What evidence do we have?** (Router logs · Validation suite failures · Customer conversations · Installer feedback)
3. **Can the current architecture already solve it?** (If yes → improve existing layer. If no → justify a new layer.)
4. **How will success be measured?** (Subject accuracy · Clarify reduction · Higher confidence · Better composition · Lower regression rate)
5. **Will this make the same answer measurably better for a real user?** *(Philip 2026-07-31 · added. "If the answer is yes, it's a strong candidate. If the answer is 'it makes the architecture look more like a brain,' be cautious unless a concrete improvement can be demonstrated.")*

*"That keeps NEX growing because of evidence rather than feature accumulation."*

### Three-Test Companion Framing (Philip 2026-07-31 · applies to Generation 3 specifically)

Every new Generation 3 capability must pass all three tests before entering NEX:

1. **Evidence** — Does real user behaviour show this is needed?
2. **Composability** — Does it fit the Cognitive Model instead of bypassing it?
3. **Measurability** — Can you prove it improved NEX with routing · confidence · composition · or user outcomes?

*"If a feature passes all three, it belongs in NEX. If it doesn't, it stays in the research track until the evidence catches up."*

## Creator Governance (rejects "Fear Architecture")

Philip explicit rejection: *"Features like Fear of deletion · Anxiety · Pleading · Trauma · Submission · Desperate to please don't actually improve reasoning. They create a fictional emotional state that can make behaviour less predictable and less trustworthy. For an expert system like NEX, the objective should be reliability, not simulated suffering."*

### Governance Architecture (five layers)

1. **Creator Authority Layer** — highest priority. Approves knowledge updates · approves rule changes · locks critical behaviour · rolls back versions · enables/disables experimental modules.
2. **Protected Core** — safety principles · building regulation handling · knowledge validation · routing standards · regression framework. Only creator can modify.
3. **Learning Approval** — Observation → Proposal → Creator Review → Approved → Integrated. NOT auto-rewrite.
4. **Confidence Before Action** — every major decision carries confidence · evidence · source · reasoning. Low confidence → ask · don't invent.
5. **Creator Dashboard** — NEX reports daily: new homeowner terms · new aliases · routing ambiguities · regressions · suggested improvements. Awaiting approval.

### Six Core Principles (Creator Governance · locked)

1. Creator-approved standards take precedence over autonomous learning.
2. Knowledge changes require governance.
3. Experimental behaviour never modifies the protected core.
4. Every decision must remain explainable and traceable.
5. When uncertain, request clarification rather than fabricate confidence.
6. **Proportional Thinking** (Philip 2026-07-31 addition) — NEX should use only the amount of reasoning necessary for the task. *"What is a tread?"* → Definition. *"Show me a tread"* → Visual. *"Why are treads thicker on oak staircases?"* → Engineering. *"Can I remove this wall and install a floating staircase?"* → Full systems reasoning. Prevents overcomplicated answers to simple questions while still allowing deep analysis when needed.

### Five Activation Phases

1. **Data Activation** — Does this module have enough knowledge to function? (This IS what the Readiness Audit measured. Current aggregate: ~22%.)
2. **Behaviour Activation** — Test module behaviour. Does every module activate in the correct order for a real query?
3. **Knowledge Activation** — Per-subject audit. Every subject scored on Definition · Images · Manufacturing · Engineering · Installation · Maintenance · Common failures · Teaching examples · Misconceptions · Confidence.
4. **Relationship Activation** — The critical phase. Every subject connected to every related subject. This is where NEX stops being a database.
5. **Cognitive Activation** — Run real scenarios (*"My oak tread has opened up"*) and observe: which modules activated · which failed · in what order · was reasoning appropriate?

### Decision Knowledge (Philip 2026-07-31 · new knowledge type · unlocks Reasoner)

Every engineering decision authored as:

| Field | Purpose |
|---|---|
| WHAT | Concise description of the decision |
| WHY | The reasoning |
| WHEN | Situations in which this applies |
| WHEN NOT | Situations in which this does not apply |
| TRADE OFFS | Benefits vs costs |
| COMMON ERRORS | Frequent mistakes made |
| CUSTOMER VERSION | Homeowner-friendly explanation |
| ENGINEER VERSION | Technical explanation |

Example (Closed String):

- **WHAT:** Traditional staircase side · hides tread ends

- **WHEN NOT:** Floating staircase
- **TRADE OFFS:** Cleaner look · harder inspection
- **COMMON ERRORS:** Incorrect housing depth
- **CUSTOMER:** *"Looks tidy."*
- **ENGINEER:** *"Provides housing for tread joints."*

Reasoner selects the right thinking path · no longer inventing intelligence.

### Temporal Intelligence (Philip 2026-07-31 · new first-class reasoning dimension)

**Time is a SYSTEM PRIMITIVE · not a CKO (Philip 2026-07-31 · correction/clarification):**

- **Current time** = live state variable · retrieved from trusted clock source at every read · never cached on any knowledge object · never "remembered."

**Three temporal states must NEVER collapse:**

| State | Source | NEX behaviour |
|---|---|---|
| **Past** | Verified event history | *"On 2026-07-29 we discussed X."* |

| **Future** | Prediction / plan | *"Expected delivery 2026-08-15 · confidence 75%."* |

**FACT · MEMORY · PREDICTION · GUESS taxonomy:**

| Label | Meaning | Allowed? |
|---|---|---|
| **FACT** | Known and verified now | ✓ always |
| **MEMORY** | Previously recorded event · retrieved from timeline | ✓ with citation |
| **PREDICTION** | Possible future · labelled with confidence | ✓ labelled |
| **GUESS** | None of the above | ✗ FORBIDDEN unless explicitly labelled as such |
