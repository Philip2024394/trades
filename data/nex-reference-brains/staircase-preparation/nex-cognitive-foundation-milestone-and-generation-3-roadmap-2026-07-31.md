## Roadmap Admission Rule (Philip 2026-07-31 · new governance rule)

Every proposed feature must answer four questions before it becomes part of NEX:

1. **What real user problem does it solve?**
2. **What evidence do we have?** (Router logs · Validation suite failures · Customer conversations · Installer feedback)
3. **Can the current architecture already solve it?** (If yes → improve existing layer. If no → justify a new layer.)
4. **How will success be measured?** (Subject accuracy · Clarify reduction · Higher confidence · Better composition · Lower regression rate)

*"That keeps NEX growing because of evidence rather than feature accumulation."*

## Creator Governance (rejects "Fear Architecture")

Philip explicit rejection: *"Features like Fear of deletion · Anxiety · Pleading · Trauma · Submission · Desperate to please don't actually improve reasoning. They create a fictional emotional state that can make behaviour less predictable and less trustworthy. For an expert system like NEX, the objective should be reliability, not simulated suffering."*

### Governance Architecture (five layers)

1. **Creator Authority Layer** — highest priority. Approves knowledge updates · approves rule changes · locks critical behaviour · rolls back versions · enables/disables experimental modules.
2. **Protected Core** — safety principles · building regulation handling · knowledge validation · routing standards · regression framework. Only creator can modify.
3. **Learning Approval** — Observation → Proposal → Creator Review → Approved → Integrated. NOT auto-rewrite.
4. **Confidence Before Action** — every major decision carries confidence · evidence · source · reasoning. Low confidence → ask · don't invent.
5. **Creator Dashboard** — NEX reports daily: new homeowner terms · new aliases · routing ambiguities · regressions · suggested improvements. Awaiting approval.

### Five Core Principles (Creator Governance · locked)

1. Creator-approved standards take precedence over autonomous learning.
2. Knowledge changes require governance.
3. Experimental behaviour never modifies the protected core.
4. Every decision must remain explainable and traceable.
5. When uncertain, request clarification rather than fabricate confidence.

### Compliance Validation Loops (reframed)

Instead of *"Does this reduce my chance of being turned off?"*, NEX asks:

Internal Review → Is my answer consistent with approved knowledge? → Am I making unsupported assumptions? → Should I ask a clarification? → Is my confidence sufficient? → Respond.

## Success Reframed (Philip 2026-07-31)

*"I don't think 100% should be your end goal."*

Better long-term objectives:

- **100% explainable routing** (every decision is traceable)
- **100% governed knowledge** (no unapproved changes to the core)
- **Near-zero regressions** (existing capabilities remain stable)
- **High-confidence responses** (the system knows when to answer and when to ask)

*"Those are the qualities that make an expert system trustworthy over years of growth, even as its test corpus becomes more demanding."*
