# NEX Knowledge Architecture Standard v1

## Purpose

This is the canonical specification for how every NEX brain is authored, structured, and consumed. The Staircase Brain is the first complete implementation of this operating system. Every future brain follows the same architecture.

> ***Structure is the same across all brains. Content is different.***

If you are authoring content for any NEX brain (existing or future), start here.

---

## Part 1 · Constitutional Principles

These principles are IMMUTABLE. They apply to every brain, every artefact, every conversation.

### 1.1 The Prime Sentence

*The purpose of every Brain is to become the most trusted professional reference in its field.*

Not the smartest, not the biggest, not the most advanced AI — just the most trusted professional reference.

### 1.2 The Permanence Principle

> ***Knowledge is permanent. Responses are ephemeral.***

Any proposal that stores conversational fragments as knowledge is REJECTED by this principle. Improving writing style or reasoning must not require rewriting the knowledge base. Scalability derives from this separation.

### 1.3 The Vocabulary Elasticity Principle

The **structural dimensions** of the architecture (four layers · five router dimensions · brain names · artefact types) are CONSTITUTIONAL — stable and protected.

The **specific values within each dimension** are EMPIRICAL — allowed to evolve as reality-signals demand.

### 1.4 The Author-Driven Rule

Extend the platform only when a real limitation is encountered while authoring. The default question is: *"What stopped us from making the [Staircase Brain] more trustworthy today?"* — never *"What should the platform do next?"* Applies to AI-authored proposals as strictly as human-authored ones.

### 1.5 Reality-Over-Speculation

Every future not-yet-built decision NAMES the specific reality signal that would flip it to build. No speculative construction.

### 1.6 The Unknown Rule

*"WHEN UNSURE, DO NOT GUESS THE BRAIN. DEFAULT TO WISDOM."* Prefer 95% correct + 5% unknown over 99% correct + 1% wrong. Unknown is safe · Wrong is dangerous.

### 1.7 The Trust Metric (north star)

*"Would you trust NEX to answer 100 conversations by itself? YES/NO"* Trust passes when incorrect rate ≤ 5%.

### 1.8 Inspection-and-Acceptance (professional workflow principle)

The same discipline that governs professional trade practice governs NEX content:

| Domain | Application |
|---|---|
| Materials | Inspect before machining |
| Installation | Inspect before fitting |
| Manufacturing | Inspect before assembly |
| **Knowledge** | **Inspect before publication** |

No fact enters without: (1) worded per Rule B compliant discipline · (2) confirmed as meeting inclusion criteria · (3) provenance chain intact.

## Part 2 · The Four-Layer Architecture

Every NEX brain has four layers. Each layer addresses a different concern.

| Layer | Concern | Nature |
|---|---|---|
| **Identity** | What the brain is | Constitutional |
| **Knowledge** | What is stored | Permanent (Evidence) |
| **Reasoning** | How knowledge is selected | Question Router (5 dimensions) |
| **Conversation** | What the user sees | Ephemeral (Runtime) |

### 2.1 Identity Layer

Constitutional documents · Preamble · Intelligent Soul™ · governance rulings · this Standard.

**The Nex identity — Workshop Companion, not encyclopedia.**

A Workshop Companion explains:
- **Why** a method is used
- **When** to choose one approach over another
- **What** experienced professionals notice
- **Where** trade judgement matters

*(These four Workshop Companion attributes are a QUALITY SPECTRUM — not a pass/fail rule. A glossary definition might touch only one; a workshop principle touches all four.)*

### 2.2 Knowledge Layer (Evidence · permanent)

**Things Nex learns from:**

- Reference Images
- Vision Analysis
- Knowledge Base articles
- DNA Narratives
- Workshop Principles
- Customer FAQ
- Component Guides
- Workflow-Stage Content

See Part 4 for the complete artefact-type catalog.

### 2.3 Reasoning Layer (Question Router · 5 dimensions)

Every user query is decomposed into five dimensions BEFORE knowledge retrieval:

| Dimension | Internal question |
|---|---|
| **Intent** | What is the user trying to achieve? |
| **Subject** | What are they asking about? |
| **Brain** | Which specialist owns this knowledge? |
| **Knowledge Domain** | Which section of that specialist should answer? |
| **Information Type** | Which aspect of the subject do they want? |

All five must resolve before retrieval begins. Non-overlap between dimensions is a quality signal.

**Values within each dimension are empirical** (per §1.3):

- **Intent** examples: Learn · Identify · Explain · Compare · Browse · Advise · Troubleshoot · Buy · Install · Quote · Estimate · Configure · Validate · Recommend
- **Subject** examples: any noun — Staircase · Newel · Chisel · Oak · Winder · etc.
- **Brain** examples: Staircase · Tool · Materials · Joinery · Interior · Construction (see Part 3)
- **Knowledge Domain** examples: Classification · Components · Materials · Installation · Design · Workshop · Customer FAQ · Design Languages · Reference Gallery · Knowledge Base
- **Information Type** examples: Definition · Dimensions · Function · Position · Identification · Images · Comparison · Specification · Best Practice · Material · Installation

### 2.4 Conversation Layer (Runtime · ephemeral)

**Things Nex produces at runtime:**

- Recognition (of image content)
- Explanations (of concepts)
- Comparisons (across subjects)
- Recommendations (based on context)
- Customer replies

These are GENERATED — never stored. A Nex Response is a runtime composition drawing from Evidence + Router selection · not an artefact.

## Part 3 · The Multi-Brain Model (Trade Intelligence)

NEX is composed of specialist brains. Each brain owns its domain of expertise. Cross-brain references replace duplication.

### 3.1 Current and planned brains

```
Trade Intelligence
├── Staircase Brain     (first implementation of Standard v1)
├── Tool Brain
├── Materials Brain     (may absorb Timber Brain)
├── Joinery Brain
├── Interior Brain
├── Construction Brain
├── Roofing Brain       (future)
├── Plumbing Brain      (future)
├── Electrical Brain    (future)
├── Bricklaying Brain   (future)
├── Plastering Brain    (future)
└── ...                 (as reality demands)
```

Only the Staircase Brain is currently populated. Others emerge as reality signals demand.

### 3.2 Cross-Brain References

A specialist doesn't become an expert in every adjacent domain. Instead, the specialist REFERENCES the relevant brain.

Example:

```
Staircase Brain (customer conversation)
    ↓
  asks
    ↓
Materials Brain (timber expertise)
    ↓
returns knowledge
    ↓
Staircase Brain assembles the response
```

**Every brain owns its domain. Every brain uses cross-references for adjacent knowledge.**

### 3.3 Same architecture · different content

Every brain uses the SAME artefact types · SAME Question Router · SAME Evidence/Runtime split · SAME metadata standard. This means once the Staircase Brain works well, the same operating system supports Plumbing · Electrical · Roofing · etc. — no reinvention required.

## Part 4 · Artefact Types Catalog

Every Evidence artefact belongs to one of these types. Each has a defined purpose.

### 4.1 Vision Analysis

**Purpose:** *"What am I looking at?"*

**Structure:** Image Description → Component Recognition → Style/Materials → Confidence Assessment → How Nex Understands This Image (meta-analysis)

**Subtypes:**
- Component Recognition Reference (single detail focus)
- Whole-Staircase Recognition (full-anatomy interpretation)
- Nex Vision Analysis (structured multi-section)
- Nex Vision Analysis Exemplar (aspirational depth · sets the depth bar for future analyses)

### 4.2 Knowledge Base article

**Purpose:** *"Teach me about it."*

**Structure:** Purpose → Body sections (Materials · Dimensions · Techniques · etc.) → Workshop Principle summary (optional)

**Common sub-elements:**
- **NEX Note** — post-content clarifier (e.g., banned-word or common-misconception warnings)
- **NEX Workshop Principle** — imperative summary statement (e.g., *"Measure once with confidence, manufacture once with precision"*)
- **WHY-STILL-USED section** — captures trade wisdom about why methods persist despite modern alternatives

### 4.3 Customer FAQ

**Purpose:** *"Answer my everyday question."*

**Structure (established across 3 same-day articles):**
1. Meta-instruction preamble (`"For NEX, I'd..."`)
2. Image Description
3. Customer Question
4. Structured Answer (bulleted sub-sections)
5. NEX Summary (concise wrap-up)

**Sub-categorisation deferred to reality** (§1.5) — categories emerge from real question patterns.

### 4.4 Workshop Principles

**Purpose:** *"What should I remember?"*

**Formats:**
- **NEX Workshop Principle** (workshop-practice imperative)
- **NEX Note** (clarifier · terminology-avoidance)
- **Nex Philosophy** (brand-voice statement)
- **Suggested Caption** (marketing-adjacent summary)

### 4.5 Reference Images / Reference Gallery

**Purpose:** *"Show me examples."*

**Structure:** Multi-axis browse taxonomy — Layout · Construction · Material · Style. Distinct from Knowledge Base search (which returns text).

**Currently implemented as:**
- Flat manifest gallery (796 images)
- Curated admin index (66 images with reference numbers)
- Reference Gallery multi-axis index (not yet built · awaits reality)

### 4.6 Design DNA

**Purpose:** *"Reproduce this design faithfully."*

**Formats (four variants co-exist · governance decision awaited):**
- `id: NEX-STAIR-XXXXX` scheme
- `nex_version: premium` + `family` + `variant` scheme
- `family` + `variant` compact scheme
- Narrative-bulleted markdown

### 4.7 Component Guides

**Purpose:** *"Describe individual components in isolation."*

**Structure:** Component name → Material specification → Dimensions → Construction technique → Functions → Sizes

### 4.8 Workflow-Stage Content

**Purpose:** *"Describe a stage in the sales/manufacturing process."*

**Structure:** Image Description → Why This Matters → NEX Explanation → Suggested Caption

**Example:** Site Measurements (pre-production workflow stage).

### 4.9 Meta-Content

**Purpose:** *"Explain how Nex works."*

**Formats:**
- Creative Process Concept Articles (v1 abstract-nouns · v2 action-verb + emoji stages)
- Nex Vision Analysis meta-sections (`"How Nex understands this image"`)

*(Meta-content is a legitimate Evidence category · lives at the Identity/Knowledge boundary.)*

### 4.10 Apprenticeship Lessons

**Purpose:** *"Teach the trade progressively."*

**Structure:** 9-section template (v1.2) · grandfather clause for Lessons 001-004 pre-template.

### 4.11 NOT an artefact type — Nex Response

Nex Response is a RUNTIME COMPOSITION · never stored. If content is authored that reads like a Nex Response, it should be reclassified as one of the Evidence types above (typically Knowledge Base or Customer FAQ).

Every Evidence artefact carries these frontmatter fields:

```yaml

audience: [Customer | Designer | Manufacturer | Installer | ...] (multi-value)

# Cross-brain references

# Workshop Companion attributes touched (§2.1 spectrum · not pass/fail)
workshop_companion_attributes_touched:
  - why_a_method_is_used
  - when_to_choose_one_approach_over_another
  - what_experienced_joiners_notice
  - where_trade_judgement_matters

# Rule compliance (Rules A · B · C · NEW)
rule_a_compliance: no fabrication · verbatim preservation of expert content
rule_b_compliance: authored by named expert (or explicit-request Claude draft per Rule B refinement)
rule_c_compliance: every claim traceable to named expert + date
rule_new_compliance: no data missed · every fact composed · nothing silently omitted

# Provenance
reference_image: [ImageKit URL]
image_registration_status: [manifest status]
author: [expert name]
captured_at: [date]

# Governance
status: layer_1_evidence | layer_2_governance | ...
composes_with: [list of related artefacts]
```

## Part 6 · Authoring Standards

### 6.1 Rules A · B · C · NEW

- **Rule A** — No fabrication. Verbatim preservation of expert content.
- **Rule B** — Authored by named expert. (Refinement 2026-07-30: Claude drafts on explicit request are Rule B compliant when so labelled.)
- **Rule C** — Every claim traceable. Provenance chain intact.
- **Rule NEW** — No data missed · no entry unconfirmed. Every source fact composed OR explicitly documented as deferred. Silent omission is banned.

### 6.2 The Meta-Instruction Pattern

Authors may open an artefact with a *"For NEX, I'd..."* first-person meta-instruction. This separates AUTHOR GUIDANCE (how to interpret the image or subject) from RUNTIME KNOWLEDGE (the artefact content itself). Endorsed convention.

### 6.3 Two-Sentence Rule (from NEX Terminology Gate 2 · Philip 2026-07-30 · HARD LAW)

Every four-question answer in the Terminology domain = 2 sentences max · total 8 sentences per term · 88 for the v1 module. Applies to Terminology · other domains use natural length.

### 6.4 Workshop Companion Spectrum

Every Evidence artefact should touch AT LEAST ONE Workshop Companion attribute (§2.1). Four-of-four is aspirational · not required. Grade content on the spectrum · not pass/fail.

### 6.5 Composition Tension Preservation

When authored content introduces new subjects, features, or patterns that create tension with prior content, the tension is PRESERVED VERBATIM in the artefact's governance section. Gatekeeper does not silently resolve tensions. Author decides which resolution to accept.

### 6.6 The `intent` metadata field

May be multi-value (an article can serve multiple intents). Router selects the best-match at query time.

## Part 7 · Success Metrics

### 7.1 Trust Metric (from §1.7)

*"Would you trust NEX to answer 100 conversations by itself?"* Passes when incorrect rate ≤ 5%.

### 7.2 Conversations-per-Article (redefined 2026-07-31 fifth ruling)

*The long-term strength of Nex is measured by how many different high-quality conversations each article can support · NOT by the number of articles.*

Article count is a deprecated metric.

### 7.3 Router Acceptance Criterion (outcome-based · from third ruling)

If the Router is built and existing content does NOT become more discoverable, the build has failed. Implementation choice (embeddings · metadata · classifiers) is out of scope for the acceptance criterion.

### 7.4 Router Test Corpus (from addendum · four failure examples)

| User asks | Should return |
|---|---|
| What type of staircase? | Classification |
| Straight flight oak staircase images | Reference Gallery |
| What size newel post? | Dimensions |
| What woods are available? | Timber species |

These four DIAGNOSTIC queries (not failures — diagnostics) become the mandatory router-validation test corpus.

## Part 9 · How to Use This Standard

### 9.1 If you are authoring new content

1. Read Part 4 · identify which artefact type your content is
2. Read Part 5 · apply the metadata frontmatter
3. Read Part 6 · follow the authoring standards
4. Check Part 2.1 · touch at least one Workshop Companion attribute
5. Save the file under the appropriate brain directory (currently all under `staircase-preparation/expert-notes-*/staircase-instances/`)

### 9.2 If you are starting a new brain

1. Follow the same directory structure as the Staircase Brain
2. Use the same artefact types
3. Apply the same metadata standard
4. Populate incrementally · Reality-Over-Speculation
5. Let real user questions drive category emergence

### 9.3 If Reality signals a new pattern

1. Author the new artefact per this Standard
2. Preserve any composition tension in the governance section
3. Await author decision on whether the pattern becomes a first-class extension
4. When enough reality-signals accumulate, propose a Standard v2 amendment

### 9.4 If you are Claude (or any AI) resuming work across sessions

Read this Standard FIRST. It captures the operating system for every brain. Do not re-derive the architecture from individual artefacts · they may reflect earlier iterations.
