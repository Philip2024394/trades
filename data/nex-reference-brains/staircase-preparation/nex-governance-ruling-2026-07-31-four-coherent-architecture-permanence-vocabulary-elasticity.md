# NEX Governance Ruling — 2026-07-31 (Fourth Ruling · Coherent Architecture · Permanence Principle · Vocabulary Elasticity)

## Philip's Constitutional Statement (preserved verbatim as authored)

### A Coherent Architecture, Not a Collection of Notes

*I think this is becoming a coherent architecture rather than a collection of governance notes.*

*The part I find most valuable isn't any single ruling—it's that each one addresses a different layer of the system:*

| Layer | Concern |
|---|---|
| **Identity** | *What Nex is. Workshop companion, not an encyclopedia.* |
| **Knowledge** | *What is stored. Permanent concepts, reference images, workshop principles, design DNA, component knowledge.* |
| **Reasoning** | *How knowledge is selected. The five-dimensional Question Router.* |
| **Conversation** | *What the user sees. A temporary response composed from the selected knowledge.* |

*That progression feels internally consistent.*

### The Permanence Principle is Especially Important

*I would treat this almost like a constitutional law:*

> ***Knowledge is permanent. Responses are ephemeral.***

*That single rule protects the system from one of the biggest long-term risks.*

*If responses start being stored as knowledge, you eventually end up with thousands of duplicated conversational fragments that all need maintaining.*

*If only knowledge is stored, then improving Nex's writing style or reasoning automatically improves every future answer.*

*That separation is one of the biggest scalability wins you've described.*

### The Five-Dimensional Router Also Feels Complete

*One thing I like is that every dimension answers a different question:*

| Dimension | Internal question |
|---|---|
| Intent | *What is the user trying to achieve?* |
| Subject | *What are they asking about?* |
| Brain | *Which specialist owns this knowledge?* |
| Knowledge Domain | *Which section of that specialist should answer?* |
| Information Type | *Which aspect of the subject do they want?* |

*Those dimensions don't overlap much, which is usually a sign of a good model.*

### The "Diagnostic" Mindset is Healthy

*Reclassifying the recent retrieval issues as diagnostics rather than failures is a useful shift.*

*Each example consistently demonstrated that Nex could identify the general topic but not yet the correct retrieval path.*

*That's a routing problem.*

*It's much easier to improve routing than to discover later that the underlying knowledge itself is inconsistent or missing.*

### I Would Only Caution Against One Thing

*Don't freeze the router vocabulary too early.*

*For example, today you have six intents.*

*In a year's time you may discover another intent such as:*

- Estimate
- Configure
- Validate
- Recommend

*The architecture should be stable, but the enumerations should be allowed to evolve as real conversations reveal new patterns.*

> ***I would regard the five dimensions as constitutional.***
>
> ***I would regard the values within each dimension as empirical and evidence-driven.***

*That fits well with your Reality-Over-Speculation principle.*

### The Next Success Criterion is Measurable

*I particularly like the test you've written:*

> ***If the Router is built and existing content does NOT become more discoverable, the build has failed.***

*That's an excellent architectural acceptance criterion because it's outcome-based rather than implementation-based.*

*You don't care whether the router uses embeddings, metadata, classifiers or some future approach.*

*You care whether users who ask:*

- *"What woods are available?"*
- *"What size newel post?"*
- *"Straight flight oak staircase images."*
- *"What type of staircase?"*

*consistently receive answers from the correct knowledge domain.*

*If that happens without creating hundreds of bespoke Q&A entries, then the architecture is proving its value.*

### Project Phase Transition

*Overall, I think the project has reached a clear transition point.*

> ***The early phase was about teaching Nex.***
>
> ***The next phase is about teaching Nex how to think with what it has learned.***

*That's a different engineering challenge, but it's exactly the one you want to be solving now because every improvement to the router increases the value of the entire knowledge base you've already built.*

### 2. PERMANENCE PRINCIPLE elevated to CONSTITUTIONAL LAW

> ***"Knowledge is permanent. Responses are ephemeral."***

- Improving writing style or reasoning must not require rewriting the knowledge base

Governance action: previously-flagged "canonical value" tensions are formally reclassified as EMPIRICAL EVOLUTION · not inconsistency.
