# NEX Governance Ruling — 2026-07-31

## Philip's Constitutional Ruling (preserved verbatim as authored)

### Architecture is Maturing, Not Becoming Messy

*I actually think this is evidence that your architecture is maturing, not becoming messy.*

*You're beginning to see the difference between knowledge, recognition, teaching, and conversation. Those should not all be forced into one format.*

*I'd describe them like this:*

| Layer | Purpose | Example |
|---|---|---|
| **Vision Analysis** | *"What am I looking at?"* | Identify a No. 4 smoothing plane, bevel-edge chisel, closed string staircase. |
| **Knowledge Base** | *"Teach me about it."* | History, anatomy, uses, workshop principles, terminology. |
| **Nex Response** | *"Answer my question."* | Dynamic response assembled from the first two layers. |
| **Workshop Principles** | *"What should I remember?"* | Best practices, craftsmanship rules, professional guidance. |

*Those aren't competing formats—they're different ways of expressing the same underlying knowledge depending on the user's intent.*

### I Wouldn't Make "Nex Response" an Artefact

*This is probably the biggest architectural recommendation I'd make.*

*A Nex Response shouldn't be stored.*

*It should be generated.*

*For example:*

> **User:** Why do staircase joiners still use hand planes?
>
> **Nex internally gathers:**
> - Vision knowledge (what a hand plane is)
> - Knowledge Base (how it works)
> - Workshop Principles (why it still matters)
> - Design context (furniture-grade finish)
>
> **Then writes a fresh response.**

*That keeps the knowledge reusable instead of filling the database with conversational variants.*

### The Tool Brain Question

*I also think you've reached the point where "tools" deserve to be their own domain.*

*Instead of asking:*

> **Does the Staircase Brain own chisels?**

*I'd ask:*

> **Which brain owns professional woodworking tools?**

*Personally I'd structure it like this:*

```
Trade Intelligence
├── Staircase Brain
├── Tool Brain
├── Timber Brain
├── Joinery Brain
├── Interior Brain
└── Construction Brain
```

*Then:*

- *A chisel belongs primarily to the Tool Brain.*
- *The Staircase Brain simply says: "I use bevel-edge chisels when fitting housed strings."*
- *Exactly the same chisel could later appear in Cabinetmaking · Door manufacture · Window manufacture · Furniture · Boat building without duplicating the knowledge.*

### I Really Like the "Why Still Used" Pattern

*This is something many technical systems miss.*

*Most documentation says:*

> **This is a hand plane.**

*Professionals ask:*

> **Why are people still using this when machines exist?**

*That section captures trade wisdom rather than textbook information.*

*The same pattern works everywhere. Examples:*

- Why stair gauges are still used.
- Why framing squares still matter.
- Why housed strings are still preferred.
- Why solid timber remains popular.
- Why experienced joiners still mark by hand.

*That feels very much in keeping with the Intelligent Soul™ idea because it explains why experienced craftspeople continue to value something, not just what it is.*

### Numbered Systems

*The plane numbering is also an important lesson.*

*Instead of treating:*

- No.4
- Jack Plane

*as alternatives, Nex should understand that they're different naming systems.*

*For example:*

```
Object
   ↓
Standard name: Smoothing Plane
   ↓
Common designation: No.4
   ↓
Category: Bench Plane
```

*That's much richer than flattening everything into one label.*

### The "Papa" Observation

*I wouldn't make personal engravings part of the canonical knowledge, but I would teach Nex to notice them.*

*If someone uploads an image, Nex can say:*

> *"The handle appears to have a personal engraving reading 'Papa', suggesting the tool has been customised or gifted."*

*That's image interpretation, not product knowledge.*

### What Excites Me Most

*The biggest change I see is that Nex is no longer becoming an encyclopedia.*

*It's becoming a workshop companion.*

*An encyclopedia answers:*

> **What is a mortise chisel?**

*A workshop companion says:*

> ***A mortise chisel is designed for levering out waste from deep mortises. Even in modern workshops with CNC machinery, it's still the quickest and most precise tool for cleaning the corners of a joint where machines can't reach.***

*That's a very different experience.*

*I think that's the direction that will make Nex distinctive. Instead of storing thousands of conversational responses, continue investing in well-structured knowledge, recognition capabilities, and workshop principles. Then let Nex generate the final explanation based on the user's question and the concepts it has learned. That's a far more scalable foundation than trying to anticipate every possible question in advance.*

## Philip's Constitutional Ruling on the Question Router Problem

### The "What Type of Staircase?" Failure

*This is actually a very useful failure because it tells you where the retrieval is going wrong.*

*The user asked:*

> **"What type of staircase?"**

*Nex replied with:*

> **"Professional staircase manufacturers usually pre-machine the joints..."**

*That answer is related to staircases in general, but it is not related to the user's intent.*

### What Should Have Happened

*The query should first determine the intent before searching the knowledge.*

*For this question, the intent is:*

```
User Question
      │
      ▼
Identify staircase type
      │
      ▼
Search:
   Layout
   Construction
   String type
   Design language
      │
      ▼
Generate answer
```

*Not:*

```
Search keyword "staircase"
      │
      ▼
Return first staircase article
```

### Your Knowledge is Becoming Rich Enough

*The problem is not that you need more Q&A.*

*The problem is that Nex needs to classify the question.*

*For example:*

| User asks | Search domain |
|---|---|
| What type of staircase? | Staircase Classification |
| Is this cut string? | String Construction |
| What are these posts? | Components |
| Why use winders? | Design Decisions |
| How is this installed? | Installation |
| How long does it last? | Customer FAQ |
| What wood is this? | Materials |

*The question itself tells Nex which part of the brain to search.*

### I Would Introduce "Knowledge Domains"

*Instead of everything living under "Staircases", create searchable domains.*

```
Staircase Brain
├── Classification
├── Components
├── Construction
├── Installation
├── Design
├── Materials
├── Workshop
├── Customer FAQ
└── Design Languages
```

*Then:*

> **"What type of staircase?"** goes immediately to **Classification** — not **Installation**.

### The Answer Should Be Built

*If the uploaded image showed, for example, a quarter-turn staircase, Nex would say:*

> ***This is a quarter-turn (L-shaped) staircase.***
>
> ***It changes direction by approximately 90° and consists of two straight flights connected by either a landing or winder steps, depending on the design.***
>
> ***From the image I can also identify:***
> - *Closed string construction*
> - *Closed risers*
> - *Timber treads*
> - *Contemporary balustrade*
> - *Walnut finish*
>
> *Then offer:*
>
> ***Would you like to learn about:***
> - *Why it's called a quarter-turn*
> - *Cut string vs closed string*
> - *Winder vs landing*
> - *Stair parts*

*That feels like an expert explaining what they see.*

### I Think the Next Evolution is Not More Articles

*I think it's a Question Router.*

*Before Nex searches knowledge, it should ask internally:*

> **What is the user trying to know?**
>
> □ Classification
> □ Comparison
> □ Definition
> □ Installation
> □ Component
> □ Material
> □ Tool
> □ Design advice
> □ Troubleshooting
> □ Customer FAQ

*Only after choosing the domain should retrieval begin.*

### This is Actually Good News

*The fact that Nex answered with a valid staircase fact rather than hallucinating means the retrieval pipeline is working. It successfully found staircase knowledge—it just found the wrong class of staircase knowledge.*

*So I wouldn't solve this by writing another answer to "What type of staircase?"*

*I'd solve it by improving the routing so that:*

- *"What type of staircase?" → Classification*
- *"How is this installed?" → Installation*
- *"How long will it last?" → Customer FAQ*
- *"What tool cuts this joint?" → Tool Brain*

*Once that routing is in place, the same knowledge base you've been building becomes much more powerful because Nex will retrieve the right knowledge for the user's intent instead of the first matching staircase article.*
