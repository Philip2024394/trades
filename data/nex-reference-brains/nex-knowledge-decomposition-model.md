# NEX Knowledge Decomposition Model

## What this document IS

A philosophical / architectural model of how NEX understands knowledge. **Not runtime code. Not Phase 3 build directive.** A shared picture of the destination · a constitutional reference point.

Every future proposal · every new specialist authored · every runtime change · can now be tested against this model. Does it fit as a specialist? Does it duplicate a specialist? Does it try to become a combination profile? Does it push toward the decomposer without earning its threshold?

**The model is the compass. The constitution decides the pace.**

## What this document is NOT

- Not authorising build of the 11-dimension decomposer at runtime
- Not authorising build of clarifying-question capability (Level 3 Wisdom · deferred)
- Not authorising build of Atom Selection Before Composition (waits for 10-20 threshold)
- Not authorising creation of any specialist module without explicit Philip request or explicit Philip authoring

## The core insight (Philip 2026-07-31)

> **"NEX knows nothing about: Oak Floating Staircases.**
> **NEX knows about: Floating staircases. Oak. Glass. Traditional design. Lighting. Installation. Handrails. Finishes.**
> **She understands combinations."**

She does not know combinatorial profiles. She knows specialists and composes them.

## The old model NEX is deliberately NOT (staircase-manufacturer thinking)

> Straight staircase → Oak straight staircase → Contemporary oak staircase → Contemporary oak staircase with glass → Contemporary oak floating staircase with frameless glass

That path eventually creates thousands of combinatorial profiles. **NEX is explicitly not that.**

## NEX's internal dimensions (staircase brain · 11 dimensions)

For a staircase-brain question, NEX internally decomposes into up to 11 dimensions before responding:

| # | Dimension | Answered by (specialist) |
|---|---|---|
| 1 | TYPE | Type-family specialists (Phase 1-4 in the content roadmap) |
| 2 | STRUCTURE | Structure specialists (Floating · Cantilever · Mono Stringer · etc. · folded into Phase 1-4 by family) |
| 3 | MATERIAL | Material specialists (Phase 5) |
| 4 | STYLE | Style specialists (Phase 7) |
| 5 | BALUSTRADE | Balustrade specialists (Phase 6) |
| 6 | COMPONENT | Component specialists (currently part of Terminology + Components module) |
| 7 | APPLICATION | Application specialists (Phase 8) |
| 8 | FINISH | Finish specialists |
| 9 | LIGHTING | Lighting specialists (Phase 9) |
| 10 | INSTALLATION | Installation specialist (already exists) |
| 11 | FAQ | Customer FAQ specialist (already exists) |

Not every dimension needs to be resolved for every question — only the ones the user actually asked about or implied.

## Example decompositions

### Specific request: *"Show me an oak contemporary floating staircase with frameless glass"*

Decomposition:
- TYPE = Straight flight
- STRUCTURE = Floating
- MATERIAL = Oak
- STYLE = Contemporary
- BALUSTRADE = Frameless glass
- (others = not implied · may still be relevant)

Specialists called: Floating · Oak · Contemporary · Frameless Glass · Installation · Design · FAQ · possibly Lighting.

They talk together. Compose ONE answer.

**No profile called *"Oak Contemporary Floating Staircase with Frameless Glass"* exists. Never should.**

### Broad request: *"I want a floating staircase"*

Decomposition:
- TYPE = Straight flight
- STRUCTURE = Floating
- STYLE = unknown
- MATERIAL = unknown
- BALUSTRADE = unknown

Decision: enough knowledge to say something · but ONE clarifying question would materially improve.

Future NEX (Level 3 Wisdom · NOT built): asks *"What's most important to you? Contemporary design · Traditional appearance · Glass balustrades · Timber balustrades · Not sure."*

Current NEX (Phase 2 · what NEX actually does today): composes what it can from Floating specialist knowledge · truthfully names the gap without asking.

### Missing dimension: *"I want a traditional oak staircase"*

Decomposition:
- TYPE = unknown
- STYLE = Traditional
- MATERIAL = Oak

Decision: missing TYPE would materially improve the answer.

Future NEX (Level 3 Wisdom · NOT built): asks *"Which staircase style interests you? Straight flight · Quarter turn · Half turn · Curved · Not sure."*

Current NEX (Phase 2): composes from Traditional + Oak specialists · truthfully names the gap without asking.

## The 5-step decomposition decision flow

Every question eventually resolves through:

1. **What are they asking?** — Decompose into up to 11 dimensions.
2. **Do I understand enough?** — YES / NO.
3. **Do I collectively possess the knowledge?** — YES / NO.
4. **Would ONE question materially improve my answer?** — YES / NO **(Level 3 Wisdom · NOT built in Phase 2)**.
5. **Compose answer.**

## Alignment to the 9-phase content roadmap

- **Phases 1-4** (Types by family) = TYPE + STRUCTURE specialists (each family folds its structural variants: Floating · Cantilever · Mono Stringer · etc.)
- **Phase 5** = MATERIAL specialists
- **Phase 6** = BALUSTRADE specialists
- **Phase 7** = STYLE specialists
- **Phase 8** = APPLICATION specialists
- **Phase 9** = LIGHTING + other accessory specialists
- **Existing modules** · Installation · Design · FAQ = the operational specialists already in place

Total ~50 specialists across all phases. Not 500 combination profiles.

## What this changes about the roadmap itself

The 9-phase roadmap remains the same. What changes is HOW each phase is understood:

- Each phase is **a set of specialists** · not a set of documents
- Each specialist is **role-specific and self-contained** · never a combination
- Cross-specialist relationships are **runtime composition** · not authoring-time merging
- The Types phases (1-4) do NOT contain material or balustrade or style content — those live in their own phases
- Cross-references are fine ("see Oak specialist for movement characteristics"); content duplication is not

## The distinction Phase 2 has been discovering

- **Old thinking:** *"we need more atoms · we need more content · we need more coverage"*
- **New thinking:** *"we need the right specialists · in the right shape · composing at runtime"*

That is the shift from a knowledge base to a knowledge intelligence system.

## Standing statement

NEX is not a library of documents. NEX is a room of specialists who understand how to talk together about a subject. Everything the constitution has been protecting exists to keep that room truthful.

## Addendum · The purpose of decomposition (Philip 2026-07-31)

> **Knowledge Decomposition is not the final stage of understanding. The purpose of decomposition is to allow NEX to determine what the user is really trying to know before knowledge composition begins.**

The 11 dimensions are not the intelligence. They are one tool that allows NEX to understand the question. The intelligence is actually this question:

> **"What is this human really trying to know?"**
